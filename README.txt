Project: Multi-source Satellite–Altimetry Based Drawdown Topography Reconstruction

This repository provides a workflow for reconstructing reservoir/lake drawdown topography by integrating SWOT raster products, ICESat-2 elevation observations, and auxiliary water body datasets. The code requires a fixed and consistent directory structure for all input data sources. Please organize your data strictly according to the specifications below before running the workflow.

Required Root Directories

The following directory paths must be defined prior to execution:

swot_root_dir 
inventory_root_dir 
waterbody_root_dir 
icesat2_root_dir 
output_root_dir 

Each root directory corresponds to one data source and must share the same site (object) identifiers.

SWOT Data Directory (swot_root_dir)

This directory stores SWOT water surface elevation (WSE) raster data and the corresponding quality flag layers.

Directory structure:

SWOT
└── site_id
├── wse
│ └── *.tif
└── wse_qual
│ └── *.tif

Description:

Each site (or object) has an individual folder named by site_id.

The “wse” folder contains SWOT water surface elevation GeoTIFF files.

The “wse_qual” folder contains the corresponding quality flag GeoTIFF files.

Files in “wse” and “wse_qual” must be temporally consistent and matched.

Inventory Data Directory (inventory_root_dir)

This directory contains the maximum water body extent for each site.

Directory structure:

Inventory
└── site_id
└── site_id.(shp)

Description:

Each site has a dedicated folder named by site_id.

The file represents the maximum observed water body extent.

This dataset is used to constrain the spatial analysis domain.

Monthly Water Body Masks (waterbody_root_dir)

This directory stores monthly water body extents for each site.

Directory structure:

WaterBody
└── site_id
├── yyyy_mm.shp
├── yyyy_mm.shp
└── ...

Description:

Each site folder is named by site_id.

Monthly water body masks are named using the format “yyyy_mm”.

These masks are used to identify temporal drawdown zones.

ICESat-2 Elevation Data (icesat2_root_dir)

This directory contains processed ICESat-2 elevation samples located within the drawdown zone.

Directory structure:

ICESat-2
└── site_id
└── Process
└── 06_Clear
└── site_id.shp

Description:

Each site folder is named by site_id.

The shapefile “site_id.shp” contains all ICESat-2 elevation points that fall within the drawdown zone.

The data are assumed to be pre-filtered and quality-controlled.

Output Directory (output_root_dir)

All results generated by the workflow will be written to this directory.

Directory structure (example):

result

Description:

Output data are organized by site_id.

Subdirectories are created automatically during processing.

Ensure sufficient disk space and write permissions before execution.

Important Notes

The site_id must be identical across all root directories.

Missing folders or inconsistent naming will result in runtime errors.

All spatial datasets should use a consistent coordinate reference system.

Do not modify the directory structure after processing has started.
